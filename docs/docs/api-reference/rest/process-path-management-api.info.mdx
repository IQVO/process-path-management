Operator-configurable process-path catalogue: canonical identity, the matchPrefix rule downstream consumers use to resolve a caller-supplied id to a path family, and the capabilities a station/associate must hold to work that path. This service replaces what was, before it existed, a static YAML file (warehouse-infra/config/process-paths/sortable-fc.yaml) loaded once at boot by fulfillment-execution, wes-work-planning, and workforce-management. It is the SOURCE of the process-path published language, never a consumer of anyone else's — every change here is propagated onward exclusively via Kafka (see apis/asyncapi.yaml), never through a synchronous callback into this service.

This API follows the fleet REST API guideline (ADR 0040): URLs name things, `POST /process-paths` is behind the Idempotency-Key middleware (a retry replays the stored answer with the response header `Idempotency-Replayed: true`; the same key with a different method, path or body is 409 `idempotency-key-reused`; a missing key is 400 `idempotency-key-required`), `PUT` and `DELETE` are idempotent by method and take no key, and the collection `GET /process-paths` is keyset-paginated as `{items, nextCursor}` with `limit` and `cursor`.
